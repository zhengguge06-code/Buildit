# Vibe 产品选品规则

这份规则用于约束 `Vibe 产品` 的收录边界，避免它再次退回“按抽象设计维度分类”的案例库。

## 一句话定位

`Vibe 产品` 不是工具榜单，也不是纯审美灵感区，而是：

- 看有哪些成熟的产品类型
- 快速判断这个方向值不值得参考
- 继续看它最值得借鉴哪里

## 用户来这里想完成什么

用户来 `Vibe 产品`，通常不是为了选数据库、选模型、选 IDE。

他们更常见的任务是：

1. 找对标
2. 看某一类产品已经被做成什么样
3. 拆首页、结构、增长机制或平台形态

所以收录时优先保证两件事：

- 它是一个真实的产品案例
- 我们能明确说出它的主分类和 badge

## 明确不收

下面这些不进入 `Vibe 产品`：

- 纯基础设施
- 通用 AI 模型入口
- 编程 IDE
- Agent 编程工具
- 后端平台
- 自动化平台
- 部署平台

这些统一归到 `Vibe 工具`。

## 分类原则

`Vibe 产品` 先按产品类型归主分类：

- `效率协作`
- `内容创作`
- `多媒体`
- `学习教育`
- `营销增长`
- `商业金融`
- `健康生活`

然后再补 badge：

- `reference_badges`
- `capability_badges`
- `platform_badges`

## 选品判断问题

每次决定一个产品要不要进库，先问这 4 个问题：

1. 这是一个成品产品，而不是基础工具吗？
2. 用户看到它后，会不会立刻知道“这是哪一类产品”？
3. 我们能不能明确说出它最值得拆哪里？
4. 它和 `Vibe 工具` 的角色边界是否清楚？

只要第 4 个问题答案不清楚，就优先不收。

## 录入规则

### 主分类

必须只选 1 个主分类。

### Badge

允许多值。

当前由后台或脚本维护，普通投稿不填写。

### 文案

文案不要再写“当前归在页面设计 / 交互体验 / 信息架构”。

改为：

- 先写它是什么类型的产品
- 再写它值得借鉴的具体点

## 当前阶段偏好

优先收录：

- 效率协作型产品
- 创作者产品
- 多媒体创作产品
- 小而成熟的增长产品
- 商业金融和生活方式里表达清楚的产品

控制收录：

- 与 `Vibe 工具` 边界模糊的平台
- 只是大厂通用入口、但没有明确参考价值的产品
