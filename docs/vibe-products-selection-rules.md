# Vibe 产品选品规则

这份规则用来约束 `Vibe 产品` 的收录边界，避免它和 `Vibe 工具` 混在一起。

## 一句话定位

`Vibe 产品` 不是“AI 工具榜单”，而是：

- 看别人已经做出了什么产品
- 看这些产品哪里值得借鉴
- 一边找方向，一边拆表达、结构、转化和品牌

## 用户来这里想看什么

用户来到 `Vibe 产品`，核心不是为了找基础设施，也不是为了选模型、选 IDE、选后端。

他们更想看两类东西：

1. 别人已经做出来的、值得研究的产品案例
2. 少量成熟大产品里，特别值得借鉴的表达或结构样本

## 收录比例

为了避免页面被“巨头产品大全”占满，候选池按下面这个比例控制：

- 70%：独立开发者、创业团队、成长型团队做出来的真实产品
- 30%：成熟大产品中确实值得借鉴的样本

## 明确不收

下面这些不进 `Vibe 产品`：

- 基础模型入口
- 通用 AI 对话工具
- 编程 IDE
- Agent 编程工具
- 后端基础设施
- 自动化平台
- 部署平台

这些都应该归到 `Vibe 工具`。

## 选品判断问题

每次决定一个产品要不要进库，先问这 4 个问题：

1. 这是一个“成品产品”吗，而不是基础工具吗？
2. 用户看到它之后，会不会觉得“这个方向我也可以做”？
3. 我们能不能明确说出它最值得学的是哪一部分？
4. 它和 `Vibe 工具` 的角色有没有重叠？

只要第 4 个问题答案偏向“有重叠”，优先不收。

## 当前收录偏好

当前阶段更优先收录这些类型：

- 创作者产品
- 效率型 SaaS
- 独立开发者产品
- 产品感强的 AI Web 应用
- 结构清晰、表达成熟的业务产品

## 当前有意控制的类型

下面这些不是完全不收，但会更克制：

- 超级巨头的一般性产品页
- 已经被太多人反复分析的通用 AI 聊天产品
- 和 `Vibe 工具` 角色边界模糊的 AI 平台

## 分类原则

`Vibe 产品` 依然按“最值得借鉴的参考维度”分：

- `界面表现`
- `交互体验`
- `产品结构`
- `商业转化`
- `增长运营`
- `品牌表达`

不是看它属于什么行业，而是看它最值得学哪一部分。
